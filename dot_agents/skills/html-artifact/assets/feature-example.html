    Design review and done checks in the planning loop

    Before a project-size spec is planned, a fresh Claude reviewer and a Codex reviewer check it against your own recorded words and its done checks, and only you see the result, on this kind of page. It serves you reading one summary page per feature instead of specs and plans. It exists because SuperFocus's costliest misses, a login choice nobody asked you about and a dashboard with no way to create a season, started in the spec, where code review never looks.

    Eight parts of the approved plan changed during review and the build

    • User journeys became done checks that fit the work, at your request, so science code gets known answers and properties.
    • Check order: done checks now run before the final code review, which needs their evidence.
    • Intent trace: an exclusion counts only when you approved it, so "out of scope" cannot hide a request.
    • Intent file: answers sit beside their questions and options.
    • Drift moved into the design review; nothing else would have triggered it.
    • Summary page is refreshed before SDD deletes its workspace, from an amendment log that lives in the intent file.
    • Claude finder at the deep tier: the deep tier already alternates vendors across lenses.
    • SuperFocus recipe and REVIEW.md rules wait for the pilot plan.

    The workflow is reviewed but not yet run on a real spec

    Codex found nine problems in the plan and one in the implementation; Claude verifiers confirmed all ten, and every one is fixed.
    • No design review has run on a real spec yet. Mitigation: the known-answer check above replays the SuperFocus spec whose miss is already known.
    • An agent in a long brainstorm may skip the intent file. Mitigation: the global bullet requires it as you answer, and the review marks its intent lens partial when the file is missing.
    • Each project-size feature costs about six more agent runs. Mitigation: quick tasks and small changes skip the design review.

    Not doing

    • Asking you to read specs or plans; you read this page.
    • A locked spec, mandatory TDD inside the agent loop, finding quotas, debate rounds or persona pipelines.
    • A scheduled drift job.
