    Nightly ingest pipeline: where the time goes

    The nightly run takes 47 minutes, and 31 of them are the embedding stage. Nothing else is worth optimising until that stage is batched.

    Four stages, one bottleneck

    Fetch and parse are bound by the source sites and finish in a stable 11 minutes. Publish rebuilds the index in place. Embed sends one request per record.

    Recommendation

    Batch embed requests at 64 records and run four workers. A dry run on one night's corpus brought the stage from 31 to 9 minutes.
    Four workers is the model API's per-key concurrency limit. A fifth worker triggers throttling, which costs more than it saves.
    If the p95 record grows past 8,000 tokens the batch fails whole. The batcher needs a per-record token cap before the flag goes on for all nights.

    Rollout steps

    week 1
    Batching behind a flag, compared against the current path on one night.
    week 2
    Flag on for all nights; watch the p95 for throttling.
    after
    Remove the sequential path once two clean weeks are logged.

    """Yield fixed-size batches; the tail batch is short."""
    for i in range(0, len(records), size):
        yield records[i:i + size]  # one request per batch, not per record
